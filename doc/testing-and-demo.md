# 作业验收、测试与录屏指南

本指南以 [mainline.md](mainline.md) 为业务依据，记录当前实现的测试边界、待验收用例和作业展示顺序。它不替代产品主线，不把计划中的能力视为已经完成。

## 1. 如何理解老师的要求

根据老师截图，作业涉及 AI 工具生成网页、自动化测试（提到了 `@browser-user`）、RN 基础 App，以及使用 Codex / Antigravity 对网页与 App 进行测试。

建议交付以下证据：

1. 一个可访问的 Web 地址和可在手机运行的 RN App。
2. AI 辅助设计与开发的过程摘要：需求、设计、实现、发现问题并修复的实例。
3. 自动化测试实际执行过程和结果，包含正常路径及异常路径。
4. 真实浏览器与 iOS / Android 设备的界面和交互验收记录。
5. 一段讲清产品用途、运行过程、测试结果和当前限制的视频。

截图没有明确规定视频长度，也无法单凭截图确定三个工具是否必须全部使用。若老师要求分别展示某个工具，需要保留该工具实际运行的证据；不要用终端单元测试替代指定浏览器工具的操作录像。

Cloudflare 上线与 GitHub 自动部署可以作为成果展示，但不能替代测试。

## 3. 从代码审查发现的移动端缺口

以下是源码检查结论，尚未用本轮真机录像确认。修复后应增加相应回归测试。

| 编号 | 位置 | 当前行为 | 验收处理 |
| --- | --- | --- | --- |
| M-01 | `app/project/[id]/submit.tsx` | “确认释放”仅跳转交易页，没有执行释放或更新里程碑、余额、待处理列表 | 若展示业务闭环，需先补完整本地模拟状态流转；不能描述为释放成功 |
| M-02 | `src/features/home/HomeScreen.tsx` | 通知按钮没有处理动作 | 实现有意义的反馈，或取消可点击表现 |
| M-03 | `src/features/settings/SettingsScreen.tsx` | 默认网络、合约设置回调为空 | 固定信息应改为清晰的只读展示，或实现对应设置 |
| M-04 | `app/project/[id]/submit.tsx` | 直接读取未本地化的项目 / 里程碑数据；无效项目 ID 回退到首个项目 | 验证中文内容一致性；无效 ID 应呈现明确的未找到状态 |
| M-05 | `src/features/projects/ProjectDetail.tsx` | 显示固定合约地址和“已验证”类文案；未接入真实合约 | 应明确标记演示数据，避免误导为链上验证结果 |

Web 已有的业务测试不能自动覆盖 Mobile 的实现。两端页面相似，也不代表逻辑与完成程度一致。当前 Mobile 适合描述为 RN 界面与交互原型，完整模拟业务闭环还需要补齐。

Expo Web 预览只能帮助检查部分跨端逻辑，不能替代 iOS / Android 真机。当前环境没有连接手机控制能力，不应宣称 AI 已经在设备上操作完成。

移动端自动化可按 Expo 官方方案补充 `jest-expo` 与 React Native Testing Library，优先测设置持久化、语言弹层、导航和修复后的状态流转。项目使用 SDK 57；若使用 Expo Router testing-library，应遵循官方文档中 SDK 57 对 React Native Testing Library 13.x 的要求，不直接混用 SDK 58 的配置。原生端到端测试可在后续加入有设备环境的测试工具链，不把安装模拟器作为本次作业唯一前提。

参考：[Expo 单元测试](https://docs.expo.dev/develop/unit-testing/)、[Expo Router 测试配置](https://docs.expo.dev/router/reference/testing/)。

## 6. 视频录制脚本

建议录制约 8–12 分钟；这是组织建议，不是老师规定的时长。电脑录屏展示 Web、代码和自动化运行，手机使用系统录屏展示原生界面，最后剪辑到同一个视频。不要只录生成代码的过程。

| 时间建议 | 画面与操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:40 | 产品首页 + 一句话业务说明 | 面向独立开发者/设计师的里程碑交付与托管演示；当前是本地模拟数据，无真实资金 |
| 0:40–1:30 | mainline、UI 设计、关键修改记录 | 展示需求如何约束实现，举安全区域或表单预览布局修复的例子；如老师要求多个工具，展示各自真实使用记录 |
| 1:30–4:00 | 浏览器 AI 操作线上 Web | 演示新建、校验错误、托管、提交、审核；保留一条失败重试，不只展示成功路径 |
| 4:00–5:00 | 终端 Web 测试 + 检查结果 | 展示真实执行与 21 项通过；说明这是逻辑与 DOM 测试，再展示浏览器尺寸/缩放检查 |
| 5:00–7:30 | iOS 与 Android 系统录屏 | 展示 Tab、滚动、安全区域、详情、语言与主题持久化；业务尚未补齐时直接说明，不伪装交易成功 |
| 7:30–8:30 | GitHub 提交、Cloudflare 成功部署、在线刷新 | 说明代码推送如何触发构建，访问的是 Web；原生 App 不由 Cloudflare 生成安装包 |
| 8:30–9:30 | 测试报告与限制 | 展示一项真实缺陷的发现→修复→复测证据；说明没有完成的项和下一步 |

录制前准备独立测试数据、收起无关窗口。OAuth 登录回调、令牌、密码和私钥不出现在录像中。无需把漫长安装、等待构建或全部聊天历史录进去。
